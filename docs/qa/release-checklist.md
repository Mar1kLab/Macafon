## Открытые ограничения

- NFR-L2: Lite имеет 20 мс алгоритмической задержки (кадр адаптера + overlap RNNoise),
  22,67 мс в приватном графе вместо ≤13 мс. Задержка в протоколе отражает реальность.
- NFR-R6: deb `Installed-Size` около 58 МиБ; цель <30 МБ не выполнена.
- NFR-R1…R3: микробенчмарки не заменяют замер CPU на Ryzen 5 3600 / i5-10400.
- NFR-R4: локально без захвата аудио Raw RSS ≈12 МиБ, Studio RSS ≈49 МиБ
  (peak ≈51 МиБ). Natural под аудионагрузкой за 90 с: RSS 13,6 МиБ, CPU 4,86% одного ядра. Для эталонной машины и A/B требуется отдельный замер.
- NFR-S3: рабочий поток Studio измеряет бюджет 8 мс на кадр 10 мс и три превышения,
  а RT-адаптер обнаруживает пропущенные результаты. Измерение времени всего callback
  относительно quantum не подключено; hook в engine пока предназначен для внешнего профайлера.
- Часовой soak при одновременной тяжёлой компиляции показал xrun; это не подтверждает
  выполнение NFR-S5. Повторный прогон без компиляции также зафиксировал 2 xrun за 90 с; максимальное время callback 1,35 мс при бюджете 2,67 мс. На этом стенде realtime priority limit = 0; это не позволяет приписать сбой только DSP и не подтверждает NFR-S5 на эталонной машине.

## Пакеты и лицензии

Сборка локальная, без CI и публикации. `target/release/bundle/` содержит артефакты;
`target/package-linux/aur/macafon-bin/` — рецепт с SHA256 конкретного deb.
Исходный AUR-рецепт в `packaging/aur/macafon/` использует релизный тег `v0.1.0`;
для публикации сначала нужны этот тег и соответствующие GitHub release assets.

Приложение — GPL-3.0-only; `macafon-dsp` и `macafon-studio` — MIT OR Apache-2.0.
Тексты лицензий зависимостей и шрифтов собираются в ресурсы пакета. Модель DFN3 встроена;
во время работы загрузки из сети нет. Звуковые фикстуры имеют отдельную атрибуцию рядом с WAV.

AppImage требует установленного PipeWire ≥1.0 и его клиентской библиотеки: linuxdeploy
исключает `libpipewire-0.3.so.0` из бандла. На стенде без FUSE запуск проверен через
`--appimage-extract-and-run`, с локально распакованными PipeWire/GTK-зависимостями.

При повторном `tauri bundle` упаковщик предупреждает о маркере `__TAURI_BUNDLE_TYPE`
в уже пропатченном бинаре. Пакеты собраны и CLI/демон запущены; updater в M1 не используется.
